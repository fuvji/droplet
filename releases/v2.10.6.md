# Droplet 2.10.6 — idle sprint poll floor

Released 2026-11-11.

Droplet 2.10.6 reduces the sprint watcher's idle wake rate. It is a runtime
scheduling change, not an input-latency or binary-size claim.

## What changed

- While the focus gate or sprint feature is inactive, the sprint watcher parks
  for **100 ms** instead of waking every **8 ms**.
- Settings publishes and focus-gate changes call `unpark`, so activation is not
  delayed by the idle interval.
- While armed, the watcher still polls every 8 ms so the 100 ms sprint pulse
  schedule is not rounded up. The sprint deadline resets on the idle path.
- The cached enable flags and settings-lock avoidance from 2.10.5 remain.
- The 2.10.4 transparent mark, focus-only presence cache, and click-through
  corners remain.

## Verification

- `cargo test --release`: **26 / 26**.
- Portable executable: **598,528 bytes**. This is 1,536 bytes larger than
  2.10.5; no size reduction is claimed.
- SHA-256:
  `9452d73bf5d4126b27d2d350eeec0b2edca78ab65b7e4137b04a0045660bb6d5`.
- Four native captures regenerated from the 2.10.6 build.
- Scheduled idle polls fall from roughly 125/s to 10/s by inspection of the
  loop interval. This is not an end-to-end latency or CPU measurement.
- Trigger routing remains 0.45 ns indexed versus 202.39 ns scanned.
- No live Minecraft client was available for positive detection or in-game
  Anchor validation. The Windows 10 GDI-region fallback was not exercised.

## Boundaries

No zero-latency, instant-speed, or frame-time claim. The game tick, Windows
scheduler, input stack, and client remain. No game-memory access, process
injection, hiding, anti-cheat bypass, input disguise, capture evasion,
telemetry, or network calls.
