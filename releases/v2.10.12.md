# Droplet 2.10.12

Released 2026-11-16. This release fixes two device-dependent defects and keeps
the tagged-source release pipeline from 2.10.12. The panel now uses an
authoritative GDI window region for its rounded silhouette on every supported
Windows version, and low-latency mode holds and reasserts the kernel timer
request instead of relying on a single startup call. No input-routing speedup
is claimed.

## Highlights

- **Complete rounded corners on Windows 10.** The window region is installed
  with `SetWindowRgn` before any compositor fallback. Windows 10 can report
  success for the newer DWM corner attribute while still drawing a square
  popup, so DWM is no longer allowed to suppress the real clip. The 8 px
  logical radius is scaled by the monitor DPI, a failed `SetWindowRgn` deletes
  its orphaned region, and `WM_DPICHANGED` replaces the old clip rather than
  leaving a stale one. The transparent quarter-rounds remain click-through.
- **The timer request targets the finest available resolution.** The previous
  code treated `NtQueryTimerResolution`'s coarsest value (`min`) as the floor
  and could request 15.625 ms on devices that expose 0.5 ms. It now reads the
  finest value (`max`), requests 5,000 × 100 ns when the hardware supports it,
  and records the value the kernel actually grants. The UI shows that value,
  not a promise.
- **The 0.5 ms request stays held.** A small guard started only while low
  latency is enabled queries the timer once per second and reasserts the
  request if Windows or another process raises it. Switching low latency off
  stops the guard, and a request that races with the off switch is released.
- **Low latency also keeps the system awake.** While the feature is enabled,
  Droplet holds `ES_CONTINUOUS | ES_SYSTEM_REQUIRED` through
  `SetThreadExecutionState`; switching it off or exiting clears the request.
  This prevents the system from idling into a sleep transition that can drop
  the timer request. It does not force the display on.
- **One new regression test.** The timer target helper is covered so a future
  change cannot silently request a coarser resolution again.
- **The source-built provenance path is retained.** The tag workflow installs
  the pinned GNU-hosted Rust 1.99.1 toolchain (the GNU host carries the
  self-contained Windows import libraries), checks formatting, runs the
  release tests, builds with `tools/build-release.ps1`, verifies the normalized
  SHA-256, and attests the exe and checksum with GitHub build provenance.

## Verification

- `cargo test --release --locked --target x86_64-pc-windows-gnu`: 39 passed.
- While Droplet was running with low latency enabled, `NtQueryTimerResolution`
  reported `current = 5000` (0.500 ms), and the System panel displayed
  **0.5 ms**. This host already had another 0.5 ms timer request active, so the
  reassertion path was verified by code inspection plus the kernel query, not
  by forcing a coarser global state.
- The regenerated Core capture shows all four corners clipped; the same region
  code runs on Windows 10 and 11.
- `powercfg /requests` requires administrator elevation and was not run, so
  the anti-sleep request is implemented and compiled but not independently
  observed here.
- No live Minecraft client or separate Windows 10 machine was available. Live
  injection, hit registration, and per-device timer floors remain unverified.

## Boundaries

Droplet remains local and visible. It has no game-memory access, network calls,
telemetry, streamproof/capture-evasion mode, anti-cheat bypass, input disguise,
or silent auto-updater. The portable exe is unsigned, so SmartScreen may warn.
